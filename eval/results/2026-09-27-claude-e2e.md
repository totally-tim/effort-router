# Live Claude verification, September 27, 2026

All 22 automated scenarios passed in Claude Code 2.1.283 with `claude-opus-5-5`. The working-copy plugin ran through Claude's real loader and request hooks. Ten scenarios used the live `local-decide` endpoint. Twelve used controlled classifier responses for configuration, failure handling, and credential checks. Claude generation was real in every scenario.

After the final review fixes, all four affected scenarios passed again. The final source also passed 80 plugin tests, four transcript extraction checks, and the production TypeScript check. Interactive Claude checks verified the active spinner, closing effort label, decision explanation, and mode changes.

[The aggregate JSON](2026-09-27-claude-e2e.json) contains the full suite, the final focused run, request efforts, durations, token usage, discovery decisions, and historical evaluation summaries. Raw transcripts and debug logs remain outside the repository.

## What the live tests found

Discovery tests exposed an under-routing case that the earlier offline examples missed. The classifier selected medium after inspecting scheduler synchronization code when the user requested a two-sentence explanation. Rewording the effort rubric did not fix it reliably.

The router now asks a separate work question about the code relationships the task requires the agent to understand. Its effort floor uses the existing 0.95 cumulative threshold. A repeated live test showed that this question alone still allowed the scheduler downgrade. The final policy also sets a high floor when semantic code analysis concerns inspected memory-ordering or compare-and-swap operations, subject to the configured ceiling. This guard does not depend on repository size, a filename, or comments claiming complexity. Specified typo edits and literal replies can still use low effort.

Independent Claude reviews found gaps in continuation handling, discovery failure handling, and evidence filtering. The fixes keep a continuation's effort floor through later discovery, restore at least the starting effort when new source cannot be assessed, and preserve inspected source when file listings fill the evidence window. Shadow decisions update their recorded predictions after asynchronous discovery completes. Denied tools cannot supply evidence.

Credential filtering now covers additional credential files, prefixed secret keys, quoted values, Authorization headers, URL user information, and incomplete private-key blocks. The final real Read test included synthetic canaries for these forms. None appeared in the captured classifier payload. Routing-instruction checks cover the repository summary and prior task evidence, including when the current request starts a new task. Ordinary security prose and README build instructions remain usable evidence. These filters are heuristics, not complete secret or prompt-injection detectors.

The suite also covered configuration through options and environment variables, rejected and missing keys, unreachable and hanging classifiers, manual launch effort, headless opt-in, off mode, and subagent isolation. The hanging-classifier case took 32 seconds overall because an abandoned HTTP request delayed Claude's process exit. The routing decision used its configured timeout.

The runner sends follow-up prompts through streaming JSON in the same Claude process. It fails on Claude errors, incomplete turns, permission denials, and a five-minute scenario timeout. Each scenario writes a result summary and raw stdout and stderr outside the repository.

### Interactive checks

The visible session used the working-copy plugin in enforce mode with `headless: false`. `/effort-router status` confirmed the live local-decide endpoint and a loaded key. A literal reply displayed `at low effort`; `/effort-router why` showed both the selected and sent effort as low. An explicit reasoning cue displayed xhigh on the active spinner and the closing line.

After `/effort-router shadow`, a literal reply displayed `at xhigh effort (router: low)`. Its decision record confirmed actual xhigh and predicted low. `/effort-router enforce` restored enforce mode, and the next reasoning turn showed the active xhigh spinner.

The first UI request coincided with a source reload during development. It retained xhigh with `no previous pick`. Subsequent checks ran after source edits stopped. Hot reload during a turn is not covered by the acceptance assertions.

## Independent review

Independent Claude reviews completed. The final focused review confirmed the prior-task scan, Authorization redaction, and URL credential fixes. It reported no blocking issue in that follow-up scope. Two low-severity false positives remain:

- The routing-instruction pattern can match ordinary text such as `classifier-free ... output` or a TypeScript `router:` parameter followed by `return`. The router then retains at least the baseline.
- Conservative credential filtering can omit a search whose term is `credentials`, or output containing dotted expressions such as `secrets.NPM_TOKEN`. This reduces evidence and can affect historical labels.

These limitations reduce opportunities to lower effort. The reviews are not a claim that arbitrary secrets or injected instructions are detected. The final reviewer did not independently inspect the host's budget getter or refresh implementation; local source inspection and hook tests covered those paths.
